# Faces & Heels v1.5 — Iso Action Figures

## Goal
Test the recommendation that a fixed three-quarter/isometric presentation can make grapples, throws, overlap, and character volume read more convincingly than the flat sprite view without rewriting the match engine.

## What changed
- Added `iso-stage.js`, a dependency-free Canvas 2D articulated action-figure renderer.
- Iso renderer is the default. The complete v1.4 sprite renderer remains selectable in Presentation Settings for direct comparison.
- Stone and Viper retain chunky proportions and identity colors/details rather than becoming thin polygon stick figures.
- The renderer uses pseudo-3D world coordinates, isometric projection, depth ordering, rounded shaded limbs, torso planes, soft ground shadows, and camera presets.
- Existing Forearm Smash, Clothesline, Ground Headlock, Dragon Screw, Body Slam, Vertical Suplex, pin, and kickout flows use the new renderer.
- Close-grapple/lockup pose logic is included in the renderer as an experimental presentation pose. No canonical Collar-and-Elbow rule was silently added to the match engine.
- The ring presentation was made more perspective-heavy in Iso mode while preserving HUD and action-dock behavior.

## Architecture decision
v1.5 deliberately does **not** add Three.js or downloaded 3D models. The prototype stays offline/self-contained and proves the camera/body-volume concept first. If this direction wins the side-by-side comparison, a later build can replace the Canvas vector rig with WebGL while keeping the same `Stage` API and match engine.

## Renderer contract
Both `IsoStage` and `SpriteStage` expose the same application-facing methods:
- `init()`
- `setRestingState()`
- `playPair()`
- `playPin()`
- `playKickout()`
- `pulseImpact()`
- `resetPositions()`

This keeps gameplay resolution separate from presentation.

## Known limitations
- This is a 2.5D articulated vector prototype, not true volumetric 3D geometry.
- Hand grips are choreographed by pose rather than solved with full inverse kinematics.
- The lockup pose exists only as experimental renderer logic; it is not a new authoritative move rule.
- Browser screenshot capture could not be completed in the current execution environment; Chromium headless did not complete navigation/capture. Automated source and match tests were completed.
