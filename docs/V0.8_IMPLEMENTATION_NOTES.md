# Faces & Heels v0.8 — Arena Flow Implementation Notes

This build is the first PWA implementation of the Match UX + HUD Specification v1.0.

## Implemented in v0.8

- Arena-first match composition.
- Compact mirrored Stone / Viper HUDs.
- Stamina bars, Pop / Heat pips, posture/major-condition summary.
- Fighter HUD tap opens body-status drawer.
- Direct move cards instead of mandatory category navigation.
- Optional category chips act only as filters.
- 0 / 1 / many target logic from the Smart Flow engine.
- Forearm Smash automatically targets Head.
- Dragon Screw opens Left Leg / Right Leg only when both are legal.
- Fixed costs are labels, never selectors.
- Optional Pop spend defaults to zero and lives behind one Boost control.
- Large in-arena d20 presentation instead of a permanent dice panel.
- Procedural sprite atlases generated entirely from Python/Pillow geometry.
- Runtime Canvas 2D sprite player.
- Forearm Smash attacker/defender animation pair.
- Vertical Suplex attacker/defender animation pair.
- Prone, pin and kickout sprite states.
- Hit-stop style impact flash / camera shake treatment.
- Damage/result overlays over the arena.
- Contextual Pin Now / Continue opportunity.
- Single legal Reaction displayed directly as Counter / Pass.
- Match Log drawer records auto-resolved facts and dice math.
- Semantic color roles from `faces_heels_ui_tokens_v1.json`.
- Responsive phone portrait, phone landscape, tablet and desktop CSS.
- Service-worker shell + primary sprite caching.

## Still intentionally limited

v0.8 is a vertical slice, not the full move library.

- Only a small set of move animations are authored.
- Dragon Screw currently uses the generic impact animation presentation after its real target choice.
- Flashpoint Driver reuses the suplex-style paired animation while the unique finisher animation is pending.
- Ring physics are presentation-only.
- Audio assets are not included yet.
- Multiplayer/network synchronization is not included yet.
- Full match win/loss rules are not expanded beyond the vertical slice.

## Core implementation rule

**Facts are labels. Decisions are buttons.**

The UI must continue to derive from the rules engine through the Decision Resolver rather than duplicating rules inside visual components.
