# Faces & Heels — ChatGPT Project Package

This package is organized so a new ChatGPT Project / Work session can distinguish **original rules**, **decisions made in conversation**, **design recommendations**, **technical proposals**, and **unresolved questions** without accidentally treating all material as canon.

## Recommended reading order

1. `00_START_HERE/PROJECT_CONTEXT.md`
2. `00_START_HERE/SOURCE_PRIORITY.md`
3. `01_ORIGINAL_RULES/Faces & Heels Rules.pdf`
4. `01_ORIGINAL_RULES/Rules_Organized.md`
5. `02_RULES_ANALYSIS/Rules_Completeness_Audit.md`
6. `07_CHATGPT_WORK_HANDOFF/Decision_Log.md`
7. `03_GAME_DESIGN/Touch_First_UX.md`
8. `04_TECHNICAL_DESIGN/Architecture.md`
9. `04_TECHNICAL_DESIGN/Animation_and_Sprite_System.md`
10. `06_IMPLEMENTATION/Roadmap.md`

## Folder map

- `01_ORIGINAL_RULES` — authoritative source material supplied by the creator.
- `02_RULES_ANALYSIS` — gaps and unresolved mechanics; analysis is not canon.
- `03_GAME_DESIGN` — product and UX direction discussed in chat.
- `04_TECHNICAL_DESIGN` — proposed implementation architecture.
- `05_VISUAL_DIRECTION` — generated concept images, including the simplified UI direction the user reacted positively to.
- `06_IMPLEMENTATION` — proposed build phases and testing plan.
- `07_CHATGPT_WORK_HANDOFF` — project instructions, decision log, and a ready-to-use Work kickoff prompt.
- `08_EXAMPLE_DATA` — non-canon sample data structures for implementation.

## Important rule for future work

Do not silently fill in missing game rules. The original PDF has several incomplete or ambiguous mechanics. When implementing one of those areas, present the decision explicitly and get creator approval before marking it canon.
